# GradEdge Production Launch Checklist & Handover Guide

This document is the operational guide and handover manual for the production launch of **GradEdge Academic Solutions**.

---

## 1. Production Environment Variables Reference

Configure these environment variables in your hosting provider (e.g. Vercel Project Settings → Environment Variables):

| Variable Name | Environment | Sensitive | Description & Production Value |
| :--- | :--- | :--- | :--- |
| `MOCK_SERVICES` | Production | No | **`false`**. Enforces that real API credentials must be present. Stubs never execute in production. |
| `NEXT_PUBLIC_SITE_URL` | All | No | Canonical public domain, e.g. `https://gradedge.com`. |
| `NEXT_PUBLIC_SUPABASE_URL` | All | No | Production Supabase project URL (`https://<project-ref>.supabase.co`). |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | All | No | Supabase public anonymous key for client-side Auth and queries. |
| `SUPABASE_SERVICE_ROLE_KEY` | Server-only | **Yes** | Privileged Supabase key for administrative and webhook tasks. Never expose to client. |
| `GOOGLE_CLIENT_ID` | Server-only | No | Google Cloud Console OAuth 2.0 Web Client ID. |
| `GOOGLE_CLIENT_SECRET` | Server-only | **Yes** | Google Cloud Console OAuth 2.0 Client Secret. |
| `NEXT_PUBLIC_PAYSTACK_PUBLIC_KEY` | All | No | Paystack live public key: `pk_live_...`. |
| `PAYSTACK_SECRET_KEY` | Server-only | **Yes** | Paystack live secret key: `sk_live_...`. |
| `PAYSTACK_WEBHOOK_SECRET` | Server-only | **Yes** | Secret signature token configured in Paystack Webhook settings. |
| `RESEND_API_KEY` | Server-only | **Yes** | Resend production API key: `re_...`. |
| `ADMIN_NOTIFICATION_EMAIL` | Server-only | No | Operational notification inbox: e.g. `admin@gradedge.com`. |
| `CRON_SECRET` | Server-only | **Yes** | 32+ character random hex string for securing `/api/cron/*` endpoints. |
| `NEXT_PUBLIC_PLAUSIBLE_DOMAIN` | All | No | Domain configured in Plausible (e.g. `gradedge.com`). |
| `NEXT_PUBLIC_SENTRY_DSN` | All | No | Sentry monitoring DSN (`https://...`). |
| `SENTRY_AUTH_TOKEN` | Build-only | **Yes** | Sentry token for uploading sourcemaps during build. |

## 2. Paystack Live-Mode Switchover Steps

To transition payments from test mode to live transactions:

1. **Activate Paystack Live Account**:
   - Log into the [Paystack Dashboard](https://dashboard.paystack.com).
   - Ensure business compliance registration (CAC in Nigeria or company incorporation documents) is verified and approved by Paystack.
2. **Update Environment Keys**:
   - Replace `NEXT_PUBLIC_PAYSTACK_PUBLIC_KEY` with your `pk_live_...` key.
   - Replace `PAYSTACK_SECRET_KEY` with your `sk_live_...` key.
3. **Configure Webhook Endpoint**:
   - In Paystack Dashboard → Settings → API Keys & Webhooks:
     - Set **Live Webhook URL** to: `https://gradedge.com/api/webhooks/paystack`.
     - Generate a strong Webhook Secret and save it in `PAYSTACK_WEBHOOK_SECRET`.
4. **Test Live Transaction**:
   - Run a live ₦100 or $1.00 test consultation deposit using a real debit/credit card.
   - Verify that:
     1. Webhook delivers `charge.success` with `200 OK`.
     2. Booking is confirmed and email receipt is dispatched.
     3. An invoice record is generated in the `invoices` table.

## 3. Supabase Backups & Database Reliability

1. **Point-In-Time Recovery (PITR)**:
   - Enable PITR on the Supabase Pro/Team tier. This allows restoring the database state to any specific second within the last 7 to 30 days.
2. **Daily Automated Backups**:
   - Supabase automatically takes daily logical backups. You can verify snapshots in Database → Backups.
3. **Manual Offsite Backup via CLI**:
   - Run a scheduled backup snapshot using `pg_dump`:
     ```bash
     pg_dump -h db.<project-ref>.supabase.co -U postgres -d postgres -F c -b -v -f gradedge_backup_$(date +%F).dump
     ```
4. **Row Level Security (RLS) Audit**:
   - Run `npm run test:rls` before every deployment to verify that all tables strictly block unauthorized anonymous or cross-tenant access.

## 4. Custom Domain & Email DNS Setup (SPF, DKIM, DMARC)

Configure these DNS records with your registrar or DNS provider (Cloudflare, Namecheap, Route53):

### A. Web Hosting (Vercel)
- **A Record**: `@` → `76.76.21.21`
- **CNAME Record**: `www` → `cname.vercel-dns.com`

### B. Transactional Email Authentication (Resend)
- **SPF Record** (TXT on root `@`):
  ```
  v=spf1 include:resend.com ~all
  ```
- **DKIM Records** (CNAME or TXT generated by Resend):
  - Add the two DKIM CNAME records provided in the Resend Domains dashboard (e.g., `resend._domainkey.gradedge.com`).
- **DMARC Policy Record** (TXT on `_dmarc.gradedge.com`):
  ```
  v=DMARC1; p=quarantine; rua=mailto:dmarc@gradedge.com; ruf=mailto:dmarc@gradedge.com; aspf=r; adkim=r; pct=100
  ```
- **MX Record for Inbound / Feedback**:
  - Configure feedback or admin MX records as provided by your Google Workspace or email host.

## 5. Sentry Error & Performance Monitoring

1. Create a project in [Sentry.io](https://sentry.io) named `gradedge-web` (Framework: Next.js).
2. Configure `NEXT_PUBLIC_SENTRY_DSN` in Vercel environment variables.
3. Configure Slack or email alerts for:
   - Any unhandled 500 error in API routes (`/api/bookings/*`, `/api/payments/*`).
   - Payment webhook failures.
   - Database connection timeouts.

## 6. Uptime Monitoring

Set up an external uptime monitor (e.g. [Better Uptime](https://betterstack.com) or [UptimeRobot](https://uptimerobot.com)):
- **Endpoint 1 (Homepage)**: `https://gradedge.com/` (Interval: 1 min, Expect: HTTP 200).
- **Endpoint 2 (Health Check)**: `https://gradedge.com/api/health` (Interval: 1 min, Expect: `{"status":"ok"}`).
- **SSL Expiry Monitor**: Alert 14 days before certificate expiration.

## 7. 301 Redirects & URL Canonicals

The following redirects are enforced in `next.config.ts`:
- All HTTP traffic automatically redirects to HTTPS.
- Trailing slashes are normalized (`trailingSlash: false`).
- Canonical redirects:
  - `/booking` → `/book`
  - `/apply` → `/accelerator/apply`
  - `/dashboard` → `/student`

## 9. One-Page Operations Handover Manual

### How to Run Locally
```bash
# 1. Install dependencies
npm install

# 2. Run local development server
npm run dev
# The site will be accessible at http://localhost:3005

# 3. Run unit and integration tests
npx tsx scripts/test-stage11-unit.ts
npx playwright test tests/e2e-launch-readiness.spec.ts
```

### How to Deploy
GradEdge is linked to the GitHub repository. To deploy changes:
1. Merge your approved PR into `main`.
2. Vercel automatically runs the build (`npm run build`), executes security checks, and deploys to production with zero downtime.

### How to Add a New Service
1. Insert a row into the `services` table in Supabase:
   ```sql
   INSERT INTO services (title, slug, short_description, full_description, is_active)
   VALUES ('Systematic Literature Review', 'systematic-literature-review', 'Methodological framing...', 'Full details...', true);
   ```
2. Insert prices for each supported currency into the `prices` table:
   ```sql
   INSERT INTO prices (item_id, item_type, currency, amount_minor)
   VALUES 
     ('<service_id>', 'service', 'USD', 12000),
     ('<service_id>', 'service', 'NGN', 8500000);
   ```

### How to Add a Mentor
1. Create a user account via Supabase Auth or admin seed script.
2. Update the user's role in the `profiles` table:
   ```sql
   UPDATE profiles SET role = 'mentor' WHERE email = 'mentor@example.edu';
   ```
3. Insert their academic details into `mentor_profiles`:
   ```sql
   INSERT INTO mentor_profiles (user_id, disciplines, degrees, university, bio, max_active_students)
   VALUES ('<user_id>', ARRAY['Quantitative Methods', 'Health Sciences'], 'PhD in Biostatistics', 'Imperial College London', 'Dr. Smith specializes in...', 5);
   ```

### How to Add a Membership Plan
1. Insert into `membership_plans`:
   ```sql
   INSERT INTO membership_plans (name, slug, interval, features, is_active)
   VALUES ('Doctoral Writing Cohort', 'doctoral-writing-cohort', 'monthly', '["Bi-weekly seminars", "Manuscript feedback"]'::jsonb, true);
   ```
2. Attach corresponding currency prices in the `prices` table for the plan ID.

### How to Process a Refund
1. Log into the GradEdge Admin Portal or call the authenticated refund endpoint:
   `POST /api/admin/payments/{payment_id}/refund`
2. Provide a mandatory reason (minimum 5 characters for audit compliance):
   ```json
   {
     "reason": "Student withdrew prior to first milestone as per refund policy clause 4.2",
     "amountMinor": 7500
   }
   ```
3. The system automatically:
   - Processes the refund with Paystack (or records mock refund in test mode).
   - Updates the payment status in the `payments` table to `refunded`.
   - Records an immutable audit log entry in `audit_logs`.
   - Updates student access/booking records.
